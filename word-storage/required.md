# required

## 基本信息

- **发音**: /rɪˈkwaɪəd/ (英式 & 美式)
- **词性**: 形容词 (adj.)
- **来源**: 动词 require 的过去分词形式

---

## 核心含义

### 形容词 (adj.)
- **必须的、强制的**（核心义）
- 规定的
- 必需的

> [!tip] 核心记忆
> **required = 不能缺少的** (necessity)，不是"规范的"

---

## 🔬 词根词缀分析

### 构词结构
```
required = re- (前缀) + quaerere (拉丁词根) + -ed (后缀)
```

| 组成部分 | 来源 | 含义 | 作用 |
|:--------|------|------|------|
| **re-** | 拉丁语前缀 | 反复、再一次、加强语气 | 表示动作的重复或加强 |
| **quaerere** | 拉丁词根 | 寻求、询问、追问 | 核心动词 |
| **-ed** | 英语后缀 | 过去分词标记 | 表示被动/完成 |

### 词源演变路径
```
拉丁语: requaerere (反复寻求)
    ↓
古法语: requerre
    ↓
英语 (13世纪): require
    ↓
现代义: "强烈要求、需要"
```

## 🌿 同源词族

都来自拉丁词根 **quaerere** (寻求、询问):

| 单词 | 构词 | 含义 | 记忆关联 |
|:-----|------|------|----------|
| [[query]] | 直接来自 quaerere | 询问、查询 | "询问"的直接继承 |
| [[question]] | quaerere + -tion | 问题 | "询问"的名词化 |
| [[quest]] | quaerere 的变体 | 探寻、追求 | "寻求"的动作 |
| [[request]] | re- + quest | 请求 | "反复追求" → 请求 |
| **require** | **re- + quaerere** | **要求、需要** | **反复追求 → 强烈要求** |
| [[acquire]] | ac- (向) + quaerere | 获得 | 追求而得到 |

> [!info] 词根记忆法
> 记住一套：**quaerere = "寻求、询问"**
> - query     → 查询
> - question  → 问题
> - request   → 请求（礼貌）
> - **require   → 要求（强制）** ← 最强烈的

## ⚠️ 常见误解辨析

### 误解: required = "规范的、按格式的"

**错误记忆** ❌
```
"required format" → required = 规范的
```

**正确理解** ✅
```
"required format" = 要求的格式（必须用的格式）
      ↓
required 修饰的是"必要性"，不是"规范性"
```

### 对比表格

| 单词            | 核心含义        | 强调点     | 典型用法                         |
| :------------ | ----------- | ------- | ---------------------------- |
| **required**  | **必须的、强制的** | **必要性** | required fields (必填字段)       |
| [[standard]]  | 标准的、规范的     | 通用性     | standard format (标准格式)       |
| [[mandatory]] | 强制的、义务的     | 法律性     | mandatory requirement (强制要求) |

## 🎯 技术文档中的应用

### RFC 2119 规范定义

在技术规范中，**required** 与 MUST/SHALL 同级，表示**最高强制性要求**：

| 关键词 | 含义 | 强制级别 |
|:------|------|----------|
| **MUST / REQUIRED / SHALL** | **绝对必须** | 🔴 最高 |
| SHOULD / RECOMMENDED | 推荐 | 🟡 中等 |
| MAY / OPTIONAL | 可选 | 🟢 最低 |

### 实际应用示例

```json
{
  "type": "object",
  "required": ["name", "email"],  // name 和 email 必须存在
  "properties": {
    "name": {"type": "string"},
    "email": {"type": "string"},
    "phone": {"type": "string"}   // phone 是可选的
  }
}
```
